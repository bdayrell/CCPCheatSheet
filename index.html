💻 Computação

Amazon EC2 (Elastic Compute Cloud)

Definição: Computação na nuvem - modelo IaaS (Infrastrutura as a Service)

Tipos de Instâncias

Uso Geral Balanceamento entre recursos de computação, memória e rede
Otimizadas para Computação Processamento em lote, High Performance Computing (HPC)
Otimizadas para Memória Memória de alto nível e velocidade
Computação Acelerada Aceleração por hardware (GPUs, FPGAs)
Otimizadas para Armazenamento IOPS alto para aplicações intensivas em I/O

Modelos de Preços

Sob Demanda (On Demand)

Sem compromisso, pague pelo que usar

Planos de Economia (Savings Plan)

1-3 anos, aplicavel a computing (EC2, Lambda, Fargate) flexibilidade para usar mais pelo preço com desconto

Instâncias Reservadas

1-3 anos, desconto significativo, podendo reservar capacidade. Pode ser Padrão(maior desconto) ou Conversível(maior flexibilidade)

Spot

Até 90% de desconto, podem ser interrompidas a qualquer hora pela AWS

Host Dedicado

Servidor físico dedicado, locação não compartilhada

Escalabilidade

Escalabilidade Vertical Ampliar recursos de processamento, memória e rede da mesma instância
Escalabilidade Horizontal Replicar a instância para distribuir a carga

Amazon Auto Scaling

Ajuste dinâmico ou previsto do número de instâncias. Configure:

  • Mínimo: Número mínimo de instâncias
  • Desejado: Número ideal de instâncias
  • Máximo: Número máximo de instâncias

Serviços Serverless

O termo "serverless" significa que seu código é executado em servidores, mas você não precisa provisionar ou gerenciar esses servidores.

AWS Lambda Executa código sem necessidade de provisionar ou gerenciar servidores
Amazon ECS Serviço de contêineres totalmente gerenciado (Docker)
Amazon EKS Kubernetes gerenciado pela AWS
Amazon Fargate Motor de computação serverless para ECS e EKS
💾 Armazenamento

Tipos de Armazenamento

Instance Store Volumes Fisicamente anexado à instância em execução - dados podem ser perdidos se a instância for interrompida
Amazon EBS (Elastic Block Store) Volumes virtuais persistentes. Snapshots permitem criar backups. Ideal para pequenas atualizações de blocos

Amazon S3 (Simple Storage Service)

Características Principais

  • Armazenar e recuperar dados ilimitados
  • Serviço serverless
  • Dados armazenados como objetos em buckets
  • 99,999999999% (11 noves) de durabilidade
  • Gerenciamento automático de ciclo de vida

Classes de Armazenamento S3

S3 Standard Dados acessados frequentemente - 99,99% disponibilidade, sem duração mínima
S3 Intelligent-Tiering Move automaticamente dados entre camadas baseado no padrão de acesso
S3 Standard-IA Dados acessados com pouca frequência - 30 dias mínimo, taxa de recuperação
S3 One Zone-IA Dados em uma única AZ - menor custo, menor disponibilidade (99,5%)
S3 Glacier Instant Retrieval Arquivamento com recuperação instantânea - 90 dias mínimo
S3 Glacier Flexible Retrieval Arquivamento com recuperação em minutos a horas - 90 dias mínimo
S3 Glacier Deep Archive Arquivamento de longo prazo - recuperação em horas, 180 dias mínimo

Amazon EFS (Elastic File System)

Acesso Simultâneo Múltiplas instâncias podem acessar os dados simultaneamente
Sistema Linux Sistema de arquivos compatível com Linux
Escalabilidade Automática Escala automaticamente conforme necessário
Recurso Regional Disponível em múltiplas zonas de disponibilidade
🗄️ Banco de Dados

Bancos Relacionais

Amazon RDS (Relational Database Service) Banco de dados relacional com capacidade econômica e redimensionável. Automatiza tarefas como provisionamento de hardware, configuração, patches e backups
Amazon Aurora Banco de dados relacional de classe empresarial, compatível com MySQL e PostgreSQL. Oferece alta velocidade e serviços administrativos

Bancos Não-Relacionais

Amazon DynamoDB Banco de dados NoSQL serverless. Oferece respostas rápidas e alta escalabilidade para casos de uso específicos

Serviços Especializados

Amazon Redshift Data Warehouse como serviço. Ideal para big data e business intelligence
Amazon DocumentDB Banco de documentos totalmente gerenciado que suporta cargas de trabalho MongoDB
Amazon Neptune Banco de dados de grafos para aplicações como redes sociais
Amazon QLDB Quantum Ledger Database - banco de dados de livro-razão. Útil para aplicações que precisam auditar alterações nos dados
Amazon Managed Blockchain Serviço de blockchain totalmente gerenciado

Aceleradores de Banco de Dados

Amazon ElastiCache Cache na memória para aplicações intensivas em dados e alto throughput
Amazon DAX DynamoDB Accelerator - cache na memória para DynamoDB

Migração de Banco de Dados

AWS DMS (Database Migration Service)

Facilita a migração de bancos de dados para a AWS com tempo de inatividade mínimo.

  • Bancos Homogêneos: Mesmo tipo de banco (ex: Oracle para Oracle)
  • Bancos Heterogêneos: Tipos diferentes (ex: Oracle para MySQL)
🌐 Rede e Entrega de Conteúdo

Rede Virtual

Amazon VPC (Virtual Private Cloud) Provisiona uma seção isolada da AWS Cloud através de sub-redes. Internet Gateway necessário para acesso à internet
AWS Direct Connect Conexão privada dedicada entre seu data center e uma VPC
AWS VPN Conexão segura entre sua rede local e uma VPC através da internet
AWS Transit Gateway Conecta múltiplas VPCs e redes locais através de um único gateway
Elastic Load Balancer Distribui automaticamente o tráfego de entrada entre múltiplas instâncias EC2.

AWS ELB vs. Amazon Route 53

Aspecto AWS ELB Amazon Route 53
Métodos de Roteamento(Atenção aos negritos)
  • Round Robin: Distribuição sequencial
  • Menor Número de Requisições Pendentes
  • Sessões Fixas: Mantém usuário no mesmo servidor
  • Balanceamento Entre Zonas: Distribui entre AZs
  • Roteamento Simples: Um registro, múltiplos IPs
  • Roteamento Ponderado: Por peso/prioridade
  • Roteamento por Latência: Menor tempo resposta
  • Roteamento por Failover: Alta disponibilidade
  • Roteamento Geográfico: Baseado na localização
  • Geoproximidade: Baseado na distância física
  • Múltiplos Valores: Retorna múltiplos endereços
  • Baseado em IP: Roteamento por faixa de IPs
Targets (destinos) Suportados Instâncias EC2, contêineres (ECS), funções Lambda, endereços IP Recursos AWS (ALB, NLB, CloudFront, S3, etc.) via registros Alias
Verificações de Integridade Monitora saúde dos targets registrados (EC2, contêineres, Lambda, IPs) Monitora saúde de endpoints (servidores web, verificações de integridade, alarmes CloudWatch)
Ação em Falha Remove target não saudável do pool de balanceamento Redireciona tráfego DNS para endpoints saudáveis

🏗️ Arquitetura VPC Típica

Componentes principais:

  • Internet Gateway: Porta de entrada para tráfego da internet
  • Sub-redes Públicas: Recursos acessíveis pela internet
  • Sub-redes Privadas: Recursos isolados da internet
  • Security Groups: Firewall no nível da instância
  • Network ACL: Firewall no nível da sub-rede
  • Route Tables: Direcionam o tráfego de rede

🔒 Segurança e Identidade

Modelo de Responsabilidade Compartilhada

🔄 Modelo de Responsabilidade Compartilhada

🏢 AWS - "Segurança DA Nuvem"
  • Infraestrutura física
  • Hardware e software de host
  • Virtualização
  • Serviços gerenciados
👤 Cliente - "Segurança NA Nuvem"
  • Dados do cliente
  • Identidade e acesso
  • Sistema operacional
  • Configuração de rede

Divisão de Responsabilidades

  • AWS: Segurança DA nuvem (infraestrutura, hardware, software)
  • Cliente: Segurança NA nuvem (dados, identidade, aplicações, SO)

Usuários IAM Sem permissões por padrão. Use MFA especialmente para usuário Root

🌍 Infraestrutura Global

Conceitos de Infraestrutura

Região Área geográfica com múltiplas zonas de disponibilidade
Zona de Disponibilidade (AZ) Data center único ou grupo de data centers dentro de uma região
Local de Borda (Edge Location) Pontos de presença para cache e entrega de conteúdo (CDN)

Critérios para Escolha de Região

Ordem de Prioridade:

  1. Conformidade: Requisitos legais e regulamentares
  2. Proximidade ao Cliente: Reduzir latência
  3. Serviços Disponíveis: Nem todos os serviços estão em todas as regiões
  4. Preço: Custos podem variar entre regiões

Serviços Híbridos

AWS Outposts Instala uma "mini região" em servidores on-premise, permitindo trabalho híbrido

AWS Cloud Adoption Framework (CAF)

Guia para migração para a AWS

🎯 Domínios de Transformação CAF

Tecnologia (Technology)
Migrar e modernizar infraestrutura
Processo (Process)
Digitalizar e automatizar processos
Organização (Organization)
Reimaginar modelo operacional
Produto (Product)
Reimaginar modelo de negócio

Fases do CAF 3.0

Visão (Envision) Demonstrar como a nuvem acelera resultados de negócios
Alinhamento (Align) Identificar lacunas de capacidade nas capacidades fundamentais
Lançamento (Launch) Construir e entregar iniciativas piloto em produção
Escala (Scale) Expandir iniciativas piloto para a escala desejada

🔄 6 Perspectivas do CAF

01 - Negócios (Business)
Alinhar estratégia de TI com resultados de negócios
02 - Pessoas (People)
Preparar para nuvem através de requalificação
03 - Governança (Governance)
Identificar melhores práticas para nuvem
04 - Plataforma (Platform)
Estratégia para design e implementação
05 - Segurança (Security)
Estruturar seleção de controles de segurança
06 - Operações (Operations)
Executar e manter estratégia

AWS Well-Architected Framework

Ajuda a entender como projetar e operar sistemas confiáveis, seguros, eficientes e econômicos na AWS Cloud.

6 Pilares do Well-Architected

Excelência Operacional Capacidade de suportar desenvolvimento e executar cargas de trabalho efetivamente
Segurança Capacidade de proteger dados, sistemas e ativos aproveitando tecnologias de nuvem
Confiabilidade Capacidade de uma carga de trabalho executar suas funções pretendidas consistentemente
Eficiência de Performance Usar recursos computacionais eficientemente para atender requisitos do sistema
Otimização de Custos Capacidade de executar sistemas para entregar valor de negócio ao menor preço
Sustentabilidade Impactos ambientais, especialmente consumo e eficiência de energia
